# jetpack-compose-performance — coding profile for the supplied Android template

Apply the compatible upstream state/stability, animation, effects/threading, lazy-layout and graphics guidance to actual generated code. Keep bitmap work, audio synthesis, database/JSON/file I/O and expensive collection processing off the main thread and out of composition. Cache expensive geometry/brushes in remember with complete keys or drawWithCache; do not allocate heavy graphics objects every frame. Use stable item keys for changing lists.

Drive countdown text from one session/deadline and a modest tick cadence, not one persistence write or entire forest recomposition per animation frame. Use lifecycle-aware cancellable effects; keep timers reconciled from durable timestamps, independent of how often Compose redraws. Separate frequently animated tree/leaf properties from the rest of the screen, and defer fast-changing reads to drawing/graphicsLayer/offset lambdas where appropriate. Do not write state after observing it in the same composition/draw pass. Avoid unconditional mutable-state wrappers for derived values and speculative @Stable/@Immutable annotations on collections. Use remembered derivedStateOf only when it reduces work; computedStateOf from Compose 1.13 is unavailable here.

Do not add unapproved dependencies, R8 configuration or baseline-profile modules to the fixed template. Debug/emulator timings and static review are functional evidence, not a release-performance benchmark. Verify performance claims with a suitable release build and measurements when available.
